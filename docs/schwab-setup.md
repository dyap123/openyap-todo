# Schwab finance adapter

The Finance module is read-only. It needs an HTTPS backend because GitHub Pages cannot safely hold a Schwab app secret, exchange OAuth codes, or refresh brokerage tokens. The runnable service is in `backend/`; no secrets belong in `app-config.js`, Firebase client data, browser storage, commits, chat, or screenshots. No real Schwab credentials or accounts were used for development tests.

## Server configuration

Use Node 24 or newer (the container pins Node24.21.0, confirmed available at the registry). SQLite uses the supported Node24 `node:sqlite` API; it still reports experimental status on some Node releases. In `backend/`, run `npm ci`, then `npm test`. Supply the variables from `.env.example` through the hosting provider's secret/environment settings; `npm start` runs the HTTP listener on `PORT` (8080 by default). The service does not load `.env` automatically. Default storage is SQLite at `SQLITE_PATH` (`/data/finance.sqlite`); `TOKEN_ENCRYPTION_KEY` must be present even when Schwab is not configured. For local process configuration Node supports `node --env-file=/secure/path/finance.env server.mjs`. Production requires a trusted HTTPS reverse proxy to the listener.

1. Register an approved application with [Schwab's Trader API](https://developer.schwab.com/products/trader-api--individual). Register the exact HTTPS callback `https://YOUR_API_HOST/v1/oauth/callback`. Set `SCHWAB_CLIENT_ID`, `SCHWAB_CLIENT_SECRET`, and `SCHWAB_REDIRECT_URI` on the server. The user signs into Schwab directly; this app never asks for brokerage credentials. Review the current [Schwab OAuth guide](https://developer.schwab.com/user-guides/get-started/authenticate-with-oauth) and portal application settings before connecting a real account.
2. Set `FIREBASE_PROJECT_ID=openyap-todo`, matching the existing frontend sign-in project. Use workload identity/Application Default Credentials with Firebase Auth user-read permission `firebaseauth.users.get` (revocation checking). SQLite needs no database IAM or paid Google billing. `roles/firebaseauth.viewer` is a broader predefined read-only alternative; no Auth write, RTDB or Storage role is required. Only the optional Firestore adapter needs database access. For local testing only, `GOOGLE_APPLICATION_CREDENTIALS` may point to a service-account JSON stored outside the repository.
3. For optional `FINANCE_STORE=firestore` only, create a **dedicated named Firestore database** `finance` in that project; `FIRESTORE_DATABASE_ID` can override its name. Do not use an existing broadly readable client database. Apply the deny-all client rules in `backend/firestore.rules` to that database before accepting credentials. The Admin SDK accesses it through IAM; client RTDB rules do not protect Firestore. Use the console or a separately reviewed server provisioning workflow; the Todo Pages release currently does not provision this backend or Firestore. Existing task/fitness RTDB paths remain independent. See [Firebase named databases](https://firebase.google.com/docs/firestore/manage-databases) and [Admin SDK Firestore](https://firebase.google.com/docs/reference/admin/node/firebase-admin.firestore).
4. Generate 32 random bytes for `TOKEN_ENCRYPTION_KEY`, base64 encoded, using `openssl rand -base64 32`. Keep the key in a secret manager, stable across restarts and instances. Tokens are encrypted with AES-256-GCM and authenticated against their Firebase UID. Losing or replacing the key requires users to reconnect. Protect backups and the runtime identity as well as the key.
5. Set `APP_URL=https://dyap123.github.io/openyap-todo/`. Set `ALLOWED_ORIGINS=https://dyap123.github.io` (comma-separated exact HTTPS origins; no paths or trailing slash). Do not add untrusted origins. All pages on an allowed origin share that browser security boundary. The callback redirect always uses the configured `APP_URL`, never request parameters.
6. Configure your HTTPS edge to omit query strings, cookies, Authorization headers, request bodies and response bodies from access/error/APM logs. OAuth callback queries include a short-lived code, and account responses contain private data. The Node service itself logs only its startup status. Set provider rate limits and request-size limits on the API; disable caching for every route. Keep the HTTP listener private behind the HTTPS edge. Route the start POST without cross-origin redirects so the browser's trusted `Origin` is preserved.
7. Set only the public API base in the frontend configuration: `OY_CONFIG.financeApiBase = 'https://YOUR_API_HOST'`. No trailing `/v1` is needed. Publish frontend changes only through the existing reviewed `oy deploy todo` workflow. Provision and release the separate server through an approved server hosting workflow; Pages alone will not activate Schwab.

The service returns authenticated `configured: false` status and the names of missing settings if Schwab configuration is incomplete. Malformed complete configuration fails startup. Firebase Auth credentials are still required for private status. An unconfigured frontend can explain setup without prompting for server secrets.

## API contract

All JSON routes require `Authorization: Bearer <Firebase ID token>`. The server uses `verifyIdToken(token, true)` against the configured Firebase project; it never trusts a UID from a request body. Allowed browser origins receive exact-origin CORS headers. Requests from other browser origins are refused. No cookies are required for private JSON API calls.

| Route | Result |
| --- | --- |
| `GET /v1/status` | `{configured, connected, missing: [settingNames], connectedAt: millisecondsOrNull}` |
| `POST /v1/connect` | `{url: 'https://API/v1/oauth/start', method: 'POST', ticket: opaqueOneTimeTicket}`; replaces any previous connection attempt |
| `POST /v1/disconnect` | `{connected: false}`; removes stored tokens and invalidates pending callbacks/refreshes |
| `GET /v1/portfolio` | `{accounts: [Schwab securitiesAccount wrappers], updatedAt: ISO8601}`; refreshes access token when needed |

Connect must submit a **native top-level HTML form** to `url`, method POST, encoding `application/x-www-form-urlencoded`, with a hidden field named `ticket`. Do not navigate to a ticket URL, use a GET form, or send the Firebase token in the form. `/v1/oauth/start` requires an exact trusted browser `Origin`, consumes the one-time start ticket, sets a `__Host-oy_schwab` Secure/HttpOnly/SameSite=Lax nonce cookie, then redirects to Schwab. A plain GET link from another site cannot initiate a connection. This avoids both third-party-cookie dependency and the attack where someone forwards their own connect link to another brokerage holder.

`GET /v1/oauth/callback` is public only for the OAuth return. It validates the hashed one-time state, ten-minute expiry, originating browser nonce, Firebase UID binding and current connection generation before storing tokens. Denied consent returns to the fixed app URL without a connection. Invalid/replayed/expired states return a generic JSON error. The frontend remembers only an account-bound return-to-Finance marker in sessionStorage before leaving and consumes it after sign-in; refresh status after returning if needed; no tokens or account data appear in the redirect URL.

Errors are `{error: code}` with HTTP status. Useful codes: `401 unauthorized`; `403 origin_denied`/`origin_required`; `503 not_configured`; `409 not_connected`, `reconnect_required`, `connection_changed`, `refresh_in_progress`, or `refresh_required`; `502 schwab_unavailable`/`invalid_schwab_response`. Retry a portfolio read after `refresh_required` or a short delay after `refresh_in_progress`. Reconnect when required. Provider response/error bodies are never passed through.

Only Schwab token exchanges/refreshes and `GET /trader/v1/accounts?fields=positions` are implemented. There is no generic URL proxy, order endpoint, trade action, model advice API, or price/history feed. Connected status means encrypted credentials are present, not a successful live brokerage health check. `updatedAt` is the time the response was fetched, not a claim that every underlying price is live. Educational concentration/allocation metrics should derive from the returned data and represent missing values honestly.

## SQLite persistence and hosted deployment

The existing VPS package uses SQLite and does not enable Google billing, Firestore, Cloud Run or Secret Manager. Every record is encrypted, including OAuth nonce/UID metadata, in addition to the existing UID-bound token encryption. A private directory mode0700, database/WAL/SHM files mode0600, WAL with FULL synchronization, `BEGIN IMMEDIATE` mutations and a ten-second busy timeout preserve atomic refresh leases/generations across processes and restarts. Never share this file through NFS or scale it to multiple hosts. One Docker named volume `todo_finance_data` survives image releases and rollbacks.

Back up the database using SQLite online backup or stop this service before copying the full database state; copying only a live main `.sqlite` file can miss WAL writes. Keep encrypted backups private and store the stable encryption key separately. Loss of either requires reconnecting accounts. Retain generation tombstones while requests may still be in flight. Abandoned OAuth entries remain encrypted and expire after ten minutes; remove them only through a reviewed transactional cleanup process.

`GET /health` is a public readiness probe returning `{ready, configured}` without account/setting details. It checks local SQLite availability; it does not claim that Firebase verification, approved Schwab consent, external providers or live prices are healthy. A valid stable key and Firebase project permit an honest unconfigured service before Schwab keys arrive.

Deployment files are `backend/Dockerfile`, `backend/deploy/compose.yml`, `backend/deploy/Caddy.fragment`, `backend/deploy/Caddy.global.fragment`, `tools/todo_finance_deploy.py` and `tools/todo_finance_remote.sh`. The image runs UID/GID10001 with no published port, read-only root filesystem, dropped capabilities, bounded resources and read-only Firebase identity mount. It joins only existing `openyap_edge`; Caddy forwards `/todo-finance/*` using `handle_path` to strip the prefix. Existing unrelated VPS applications are never synced or rebuilt.

The reviewer must provision `/srv/openyap/todo-finance/secrets` privately before release: `service.env` mode0600 readable by the host deploy user, containing a stable key and optional approved Schwab client ID/secret; `firebase.json` mode0400 owned UID10001, containing a dedicated Todo-project identity with only required Auth read access. Do not reuse a broad worker identity. Do not print these files, source them into shell commands, put values in process arguments, or run `docker compose config` without output suppression. Other settings are pinned in the finance compose file. Docker privileged users can inspect container environment and must be trusted.

`PUBLIC_API_BASE=https://api.openyap.org/todo-finance` must exactly match the callback `https://api.openyap.org/todo-finance/v1/oauth/callback`. The backend rejects arbitrary prefixes, queries, fragments, trailing slashes or a mismatching callback. A standalone host may omit `PUBLIC_API_BASE` and use the root `/v1/oauth/callback`. Frontend config stays empty until the reviewer has validated the live service.

Only the reviewed `oy deploy todo-finance --commit FULL_TODO_SHA --caddy-sha LIVE_CADDY_SHA256 --dry-run` target may deploy this package. The proposed dispatcher lives in an isolated central harness worktree for review; it must be accepted into the operational harness before use. Dry-run verifies clean pinned source, approved Todo remotes/branch/project and committed artifacts and prints a plan without SSH/live writes. Remove `--dry-run` only for an approved release: it runs `oy check`, backend tests, stages an archive of the exact commit, builds/starts only finance, validates the Caddy candidate with the installed Caddy, compares the live Caddy SHA again, writes the bind-mounted file without replacing its inode, and reloads Caddy.

Caddy access logs are skipped for the entire finance prefix. A named finance logger discards access records; a global logger specifically discards `http.log.error.finance_private` to protect callback queries on reverse-proxy failure. Do not enable Caddy debug/trace/request-body logging. Validate the candidate against the actual installed Caddy and perform a synthetic callback/proxy-failure log check before real OAuth. No global default logger is disabled; other applications retain their logging.

A failed remote operation restores the previous finance image and previous Caddyfile when available; it never deletes the named volume. A reviewed prior source commit can also be released through the same scoped target with a newly confirmed Caddy SHA. Existing release archives must match their immutable archive digest. No `docker compose down -v`, broad `make deploy`, `rsync --delete` or unrelated app restart is involved.

See `backend/deploy/activation-plan.json` for the proposed public endpoint and remaining inputs. The package was prepared without uploading credentials or changing a live service.

## Optional Firestore storage, cleanup and disconnect

Server-only `finance_connections` documents contain encrypted access/refresh tokens, access expiry, a connection generation, connection time and an expiring transactional refresh lease. UID document IDs are hashed. Refresh transactions prevent parallel token rotations across multiple service instances; generation checks prevent a delayed refresh/callback from restoring a disconnected account.

`finance_oauth` documents contain only a UID, generation, browser nonce, phase and ten-minute numeric expiry. Successful callbacks delete them. Abandoned documents can be removed by scheduled server-side cleanup where `expiresAt` is older than the current epoch milliseconds; their expiry is enforced even before deletion. Firestore TTL requires a Timestamp field, so do not configure TTL directly on this numeric field. Restrict both collections to server IAM and retain only as long as needed. Disconnect deletes tokens while retaining a small generation tombstone to prevent in-flight restoration.

Disconnect removes this app's stored access and refresh tokens. It does **not** claim to revoke consent at Schwab: revoke the application through Schwab's account/connected-app controls when needed. Schwab can expire or revoke refresh credentials, requiring browser consent again. No long-lived refresh validity is assumed by this adapter.

## Validation

`npm test` uses synthetic UIDs/provider responses, a transactional in-memory store and a local HTTP server. It covers configuration, token encryption/UID binding, identity/origin checks, OAuth browser binding, forwarded-link attacks, state expiry/replay, account isolation, refresh leasing, disconnect races, error redaction and transport security headers. It makes no brokerage requests or live Firebase mutations. The local HTTP test needs permission to bind localhost in restricted sandboxes.

Before production, verify the named database denies all browser reads/writes, IAM grants only the required server access, secrets and queries are excluded from host logging, the exact callback is approved at Schwab, and an end-to-end consent/refresh/disconnect succeeds with an authorized test account. Those provider/provisioning checks require the owner’s approved credentials and HTTPS host; they cannot be proven by mocked tests.

Deployment additionally validates the canonical JSON from the installed Docker Compose parser before any build/start. `backend/deploy/check-compose.py` requires exactly one quoted private `/tmp` tmpfs mount, the nonroot UID, read-only identity/root filesystem, capability restrictions, scoped volume/network/project and readiness check. Canonical environment data stays in a process pipe and is never printed. `python3 tools/todo_finance_compose_probe.py --ssh` runs the checked-in secret-free regression against the installed VPS parser using `/dev/null` instead of the secret env file; it verifies the corrected mount and rejects split tmpfs/root/published-port/writable-identity variants without starting services.

A pre-existing Caddy bind can reference an old inode even when restored contents and hashes match. The deployment now compares the host and mounted inodes. With a stale/stopped edge, `backend/deploy/edge-control.py` recreates **only** Caddy using `--no-deps --no-build --pull never --force-recreate caddy`; API/worker services remain untouched. Before this related routing-service restart, it requires the running image ID to match the existing cached Compose tag and requires the same certificate/config mounts, published ports and Docker networks. It refuses an implicit Caddy upgrade or resource change. The same guard controls rollback after restoring the previous file. When the mount is current, it uses a regular reload.

After activation it asserts inode equality and reads the live Caddy admin configuration privately to verify the public host matcher, `/todo-finance/*`, prefix stripping, intended upstream and error-log privacy. Only then do public readiness/auth probes accept the release. `tools/todo_finance_edge_test.py` covers stale/current binds, image/resource drift refusal, rollback snapshots and missing/misrouted runtime configuration. The installed-version candidate probe now requires `--candidate /srv/openyap/todo-finance/releases/FULL_SHA/Caddyfile.candidate` and tests the exact full chain against separate finance/existing-API stub servers; a second run with finance absent verifies callback error logging. Temporary listeners disable admin, HTTPS and config persistence and time out; they never replace live configuration.
